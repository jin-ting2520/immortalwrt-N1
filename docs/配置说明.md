# ImmortalWrt N1 配置说明

## 1. 网络默认值

| 项目 | 默认值 |
| --- | --- |
| N1 地址 | `192.168.123.2/24` |
| 网关、主路由 DNS | `192.168.123.1` |
| DHCP | 不提供，只保留 dnsmasq DNS |
| LuCI | HTTP `8080`，HTTPS `8443` |
| Nginx | HTTP `80`，HTTPS `443` |
| 时区 | `Asia/Shanghai` |

N1 默认作为旁路由使用：主路由负责拨号、DHCP 和外网出口，N1 只做 DNS、代理、反向代理、文件服务和组网。`/etc/config/dhcp` 只保留 `config dnsmasq`，没有任何 `config dhcp` 段，因此不会启动 DHCP 服务，客户端地址由主路由分配。

地址冲突或网段不一致时，修改 `N1/files/etc/config/network`，并同步调整 `N1/diy.sh` 里的默认地址 sed。

## 2. 文件和构建模块

| 文件或模块 | 作用 |
| --- | --- |
| `N1/config.base` | 两个版本共用的固件目标、内核模块、驱动和基础软件包。 |
| `N1/config-24.10` / `N1/config-25.12` | 版本差异配置，构建时追加到 `.config`。 |
| `N1/diy.sh` | 下载固定 tag/commit 的第三方插件（含 OpenClash、iStore）、写入插件选择、设置 Amlogic 更新标签。 |
| `N1/files` | 覆盖默认网络、DNS、系统、uhttpd、Nginx Manager 和首次启动配置。 |
| `N1/files/etc/config/dhcp` | 仅 dnsmasq DNS 配置，不含 DHCP 服务。 |
| `N1/files/etc/config/nginx_manager` | Nginx 管理器的安全默认值：上传大小、超时、压缩、TLS 会话。不会创建未知域名的反代站点。 |
| `N1/files/etc/uci-defaults/90-n1-services` | 首次启动启用 irqbalance、Nginx。 |
| `scripts/init_build_environment.sh` | 从 ImmortalWrt 固定下来的编译环境初始化脚本（GPL-2.0）。 |
| `.github/workflows/openwrt-builder.yml` | 构建 24.10/25.12、校验 rootfs、打包 N1 镜像、发布 Release、清理旧产物；push master 或手动触发。 |
| `.github/workflows/lint.yml` | push/PR 时运行 shellcheck 和 actionlint。 |

## 3. 内置程序用途

### Amlogic

提供 N1 启动、内核和固件相关支持。在线更新使用 `amlogic_firmware_tag` 按源码版本筛选 Release，`amlogic_write_bootloader` 固定为 `0`，避免误写引导。

所有构建和 Release 都发布在公开仓库 `jin-ting2520/immortalwrt-N1`，固件可以匿名读取 Release 列表，Amlogic 页面的在线更新可直接使用。

### Nginx 和 Nginx Manager

Nginx 是公网 HTTPS 入口，Nginx Manager 用 LuCI 管理站点、证书、日志和配置。项目只预置通用参数，不预设域名和后端地址。

创建反代站点：

1. 进入“服务 → Nginx Manager → Sites”。
2. 新建“反向代理”站点。
3. 填写域名和后端地址，例如 `http://127.0.0.1:5244`。
4. 需要 HTTPS 时添加证书并监听 `443`。
5. 保存后由管理器执行 `nginx -t`，测试通过才重载。

上级路由器还必须将 TCP `80/443` 转发到 `192.168.123.2`。不要把 LuCI `8080/8443` 转发到公网。

### OpenList

用于文件管理和 WebDAV。默认端口为 `5244`，建议只监听内网，并通过 Nginx 的 HTTPS 域名反代。WebDAV 的具体路径和存储目录在 OpenList 页面配置，不能在固件中猜测。

### HomeProxy

基于 sing-box 的代理平台，支持客户端、服务端、TLS、透明代理和策略路由。核心组件由依赖和显式选择保证：`sing-box`、`kmod-nft-tproxy`、`ucode-mod-digest`、`kmod-tun`、`firewall4`、`dnsmasq-full`。项目不写入 VMess 端口、UUID、证书或防火墙规则，首次使用时在“服务 → HomeProxy”按实际节点配置。

### OpenClash

基于 Clash/Meta 内核的代理平台。固件包含 `luci-app-openclash` 和运行脚本，Clash 内核由 OpenClash 页面在运行时下载。依赖 `ruby`、`ruby-yaml`、`kmod-tun`、`kmod-nft-tproxy`、`dnsmasq-full` 等。包由 ImmortalWrt LuCI feed 提供（24.10 为 0.47.156，25.12 为 0.48.002），不再从第三方仓库克隆。

OpenClash 和 HomeProxy 都会接管防火墙与 DNS，同时启用会互相覆盖；建议只启用其中一个。控制面板默认端口 `9090`。

### iStore

应用商店，包含 `luci-app-store`、`luci-lib-taskd`、`luci-lib-xterm` 和 `taskd`。它从 iStoreOS 的软件源安装插件，包 ABI 和依赖与 ImmortalWrt 不完全一致，安装前先确认兼容性，避免把系统包替换掉。

iStore 只在 **24.10** 集成；25.12 的依赖链无法选中 `luci-app-store`（Kconfig 会丢弃该选项），因此 25.12 不包含 iStore。

### Cloudflared

Cloudflare Zero Trust Tunnel 客户端，包含 `cloudflared` 和 `luci-app-cloudflared`。在 LuCI 页面填写 tunnel token 后启用，不需要在固件里预置证书或域名。25.12 的 Go feed 使用 OpenListTeam 的 27.x 替换，`diy.sh` 会把 cloudflared 的 `golang1.27/host` 依赖改写为 `golang/host`。

### DDNS-Go

负责动态域名更新和证书相关任务。域名证书的实际保存路径以 DDNS-Go 配置为准；需要给 Nginx 或 HomeProxy 使用时，应在对应页面明确填写证书和私钥路径。

### EasyTier

用于虚拟组网。项目不预置网络名称、密钥、虚拟地址、出口节点或转发规则。启用后根据实际组网网段配置接口、防火墙和到 LAN/WAN 的转发。

若希望 VMess 客户端访问 EasyTier 子网，必须同时配置：

1. HomeProxy 服务端入站和客户端路由规则。
2. EasyTier 的实际虚拟网段和接口路由。
3. OpenWrt 防火墙区域及转发。

仅安装两个插件不能自动保证该流量路径。

### Argon 主题配置

24.10 的 Argon 配置页是独立的 `luci-app-argon-config`，25.12 的 `luci-theme-argon` 已内置配置页。两个版本都安装 `luci-i18n-argon-config-zh-cn`。

### 系统工具

- **CPU 调频**：`luci-app-cpufreq` 提供 governor/频率设置，`cpufreq` 包在启动时应用。`luci-app-amlogic` 的 init 也会在开机时把它的 `armcpu` 设置写入 sysfs，两者功能重叠但不冲突包文件：amlogic 的启动顺序是 `START=60`，本项目把 `cpufreq` 调到 `START=61`，未配置 cpufreq 时它不动作，保存过设置后以 cpufreq 为准。建议只用一个 UI，避免两边值不一致。
- **断网自动重启**：`luci-app-watchcat` 按设定的目标定期检测，连续失败后重启设备。
- **证书管理**：`luci-app-acme` 提供 ACME 证书的 LuCI 页面，底层是 `acme-acmesh`。25.12 的 packages feed 移除了 `acme` shorthand，`diy.sh` 会把 `luci-app-acme` 和 `acme-acmesh-dnsapi` 的 `+acme` 依赖改写成 `+acme-acmesh`，避免空包和 Kconfig 递归依赖。
- **zram**：默认 512 MB、lz4，用于缓解 2 GB 内存下的 OpenClash/iStore 压力。

### 无线与 Docker

固件不包含无线驱动、wpad、iw，也不包含 Docker、dockerd、containerd、Docker Compose 和 Dockerman。N1 本身没有无线网卡，不需要这些组件。

## 4. 安全默认值

- LuCI 监听 `0.0.0.0:8080/8443`，但启用 `rfc1918_filter`，非内网来源会被拒绝。
- 首次登录后立即设置 root 密码；固件不预设默认密码。
- 公网只暴露 Nginx 的 `80/443`，不要转发 `8080/8443`。
- 固件不提供 DHCP 服务，也不启用无线。
- Nginx Manager 默认开启 `test_before_reload` 和 `auto_backup`，配置错误时不会直接重载。
- OpenClash 和 iStore 会在运行时从网络下载内核或软件包，只使用可信来源。

## 5. 双版本发布

Actions 使用矩阵构建：

| 源码分支 | Release 标签前缀 |
| --- | --- |
| `openwrt-24.10` | `OpenWrt_24.10_` |
| `openwrt-25.12` | `OpenWrt_25.12_` |

构建只由推送到 `master` 或手动 `workflow_dispatch` 触发；推送到其他分支和纯文档提交不会构建，新的 master 推送会取消尚未完成的旧构建。

标签格式为 `OpenWrt_<版本>_<YYYY.MM.DD-HHMM>`，从标签即可区分源码版本。每个 Release 附 `SHA256SUMS` 和 `*.manifest` 软件包清单，每个版本保留最近 2 个 Release。

手动运行时可选择内核变体：默认 `6.12.y_6.18.y`，也可选 `6.6.y_6.12.y` 或全部 7 个。构建在打包前会校验 rootfs：默认地址、无 DHCP 段、无无线配置、关键插件存在、Docker/无线包不存在；任何一项不满足都会终止构建。正式构建前执行 `make defconfig`、下载和编译；如果 defconfig 后缺少功能包，工作流也会直接失败，不会产出功能残缺的固件。
